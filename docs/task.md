### Техническое задание для сайта бронирования билетов в кинотеатр

---

#### **1. Цель проекта**
Создать веб-приложение для бронирования билетов в кинотеатр с аутентификацией пользователей, управлением сеансами, выбором мест и оплатой.

---

#### **2. Функциональные требования**
##### **2.1. Модуль аутентификации и авторизации**
- Регистрация пользователей через email и пароль.
- Вход/выход из системы.
- Восстановление пароля через email.
- JWT-токены для аутентификации.
- Ролевая модель: пользователь, администратор.
- Дополнительно: вход через OAuth2 (Google/GitHub).

##### **2.2. Модуль управления кинотеатрами и залами** (для админов)
- CRUD для кинотеатров (название, адрес, описание).
- CRUD для кинозалов (вместимость, схема расположения мест, тип зала).
- Привязка залов к кинотеатрам.

##### **2.3. Модуль расписания сеансов**
- Добавление фильмов (название, описание, постер, длительность, жанр, возрастной рейтинг).
- Создание сеансов: выбор фильма, зала, времени начала, цены билета.
- Отображение доступных сеансов с фильтрами по дате, кинотеатру, жанру.

##### **2.4. Модуль бронирования билетов**
- Просмотр схемы зала с доступными/занятыми местами.
- Выбор места и добавление в корзину.
- Резервирование мест на короткое время (15 минут) с использованием Redis.
- Оплата через интеграцию с платежной системой (например, Stripe, PayPal).
- Отмена бронирования (до момента оплаты).

##### **2.5. Личный кабинет пользователя**
- История бронирований.
- Просмотр активных и завершенных сеансов.
- Отмена бронирования (если разрешено).

##### **2.6. Административная панель**
- Управление пользователями (блокировка, смена ролей).
- Просмотр статистики: популярные фильмы, доходы, заполняемость залов.
- Настройка параметров системы (например, время резервирования).

---

#### **3. Технические требования**
##### **3.1. Стек технологий**
- **Бэкенд**: Go (с фреймворком Gin или Echo).
- **Базы данных**: 
  - PostgreSQL (основное хранилище: пользователи, сеансы, бронирования).
  - Redis (кеширование расписаний, временное хранение корзин, JWT-токены).
- **Аутентификация**: JWT с сохранением токенов в Redis для возможности инвалидации.
- **API**: RESTful (или GraphQL по желанию).
- **Фронтенд**: Может быть реализован на любом стеке (например, React/Vue.js), но в ТЗ фокусируемся на бэкенде.

##### **3.2. Безопасность**
- HTTPS для всех запросов.
- Валидация входных данных.
- Защита от SQL-инъекций и XSS.
- Ограничение частоты запросов (rate limiting) для критичных эндпоинтов.
- CSRF-токены для форм (если используется серверный рендеринг).

##### **3.3. Производительность**
- Кеширование расписаний сеансов и списка фильмов в Redis.
- Использование пула соединений с PostgreSQL.
- Оптимизация запросов к БД (индексы, частичные выборки).

---

#### **4. Структура базы данных** (основные таблицы)
1. **users**:
   - `id`, `email`, `password_hash`, `role`, `created_at`, `is_active`.
2. **cinemas**:
   - `id`, `name`, `address`, `description`.
3. **halls**:
   - `id`, `cinema_id`, `name`, `capacity`, `seat_map` (JSON-схема мест).
4. **movies**:
   - `id`, `title`, `description`, `duration`, `genre`, `age_rating`.
5. **sessions**:
   - `id`, `movie_id`, `hall_id`, `start_time`, `price`.
6. **bookings**:
   - `id`, `user_id`, `session_id`, `seats` (JSON-массив мест), `status` (reserved/paid/cancelled), `expires_at`.
7. **payments**:
   - `id`, `booking_id`, `amount`, `status`, `transaction_id`.

---

#### **5. API-эндпоинты** (примеры)
- `POST /api/auth/signup` — регистрация.
- `POST /api/auth/login` — вход.
- `GET /api/movies` — список фильмов.
- `GET /api/sessions?date=...` — расписание сеансов.
- `POST /api/bookings/reserve` — резервирование мест.
- `POST /api/payments/process` — обработка оплаты.
- `GET /api/user/bookings` — бронирования пользователя.

---

#### **6. Этапы разработки**
1. **Проектирование**:
   - Схема БД.
   - Детальное описание API.
   - Архитектура приложения (микросервисы или монолит).
2. **Бэкенд**:
   - Настройка роутинга и middleware (аутентификация, валидация).
   - Реализация CRUD для кинотеатров, залов, фильмов.
   - Модуль бронирования с Redis.
   - Интеграция с платежной системой (мок или sandbox).
3. **Фронтенд** (опционально):
   - Базовая версия на HTML/CSS/JS или современном фреймворке.
4. **Тестирование**:
   - Unit-тесты для критичных модулей (Go testing).
   - Интеграционные тесты API (Postman).
5. **Деплой**:
   - Развертывание на Heroku, AWS или другом хостинге.
   - Настройка CI/CD (GitHub Actions/GitLab CI).
